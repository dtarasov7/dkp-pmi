# Пункт 5

Платформа обеспечивает возможность интеграции с внешней системой для хранения и управления чувствительной информацией приложений в виде секретов (secrets), развернутых на ней.

## Что проверит подготовка

`01-prepare.sh` проверит готовность модуля `secrets-store-integration`,
нужные поля ресурса `SecretsStoreImport` и регистрацию драйвера
`secrets-store.csi.deckhouse.io`. Драйвер монтирует полученный секрет как файл
в контейнер. Если API или драйвера нет, подготовка завершится до создания объектов
и укажет, чего не хватает. Проверять схемы вручную не нужно.

## Что подготовить во внешнем хранилище

Готовый набор команд для отдельной ВМ РЕД ОС 7.3: [Vault в режиме dev с TLS](VAULT-REDOS-7.3.md).
Он включает установку актуального пакета, запуск на отдельном сервере без kubectl,
создание секрета и роли, TokenReview через HTTPS Ingress Deckhouse,
подключение модуля, проверку ротации и очистку. Команды для сервера Vault
и рабочей машины с kubectl указаны отдельно.
Этот вариант выполняйте **до** `01-prepare.sh`; его инструкция сама указывает,
когда перейти к трём скриптам испытания.

Эти действия выполняются на сервере секретов, поэтому Kubernetes не может проверить
их через свою схему. Нужен Vault-совместимый сервер, подключённый к модулю по HTTPS
с доверенным сертификатом. Для теста используйте только искусственные данные:

| Настройка во внешнем хранилище | Значение для этого сценария |
|---|---|
| Раздел секретов типа KV v2 | `pmi` |
| Имя секрета внутри раздела | `dkp-acceptance` |
| Ключ внутри секрета | `marker` |
| Начальное значение ключа | `pmi-value-1` |
| Роль Kubernetes-аутентификации | `pmi-5-reader` |
| Разрешённая учётная запись Kubernetes | `reader` только в namespace `pmi-5` |
| Права роли | Только чтение `pmi/data/dkp-acceptance` |

Владелец хранилища создаёт секрет и привязку роли к учётной записи. Сам namespace
и ServiceAccount `reader` создаст `01-prepare.sh`. Kubernetes-аутентификация
на внешнем сервере должна проверять токены этого кластера через TokenReview.
После создания Pod скрипт дождётся его готовности: это проверит и фактическое
получение секрета. При ошибке монтирования смотрите причину в
`kubectl -n pmi-5 describe pod reader`.

Покажите комиссии роль и её права на внешнем сервере. Root-token в Pod не передаётся.

## Демонстрация и результат

1. Запустите подготовку, затем `export EXPECTED_MARKER=pmi-value-1` и проверку.
   Файл в CSI-томе должен содержать значение внешнего секрета.
2. В интерфейсе внешнего хранилища измените **выделенный тестовый** marker на `pmi-value-2`.
   После интервала синхронизации установленной версии модуля повторите проверку с
   `export EXPECTED_MARKER=pmi-value-2`. Если версия не поддерживает авторотацию,
   зафиксируйте это и пересоздайте только reader через очистку и подготовку.
   Не выдавайте пересоздание за автоматическую ротацию.
3. Покажите запись чтения в аудите внешнего хранилища и источник CSI-тома Pod.
   Секрет не прописан в манифесте приложения; read-only CSI-файл доступен приложению.
4. После очистки Kubernetes владелец хранилища удаляет только выделенные для испытания
   секрет/версию, роль и policy; общий mount и auth backend сохраняет.

Источники: [CSI-импорт](https://deckhouse.io/modules/secrets-store-integration/usage.html),
[схема SecretsStoreImport](https://deckhouse.io/modules/secrets-store-integration/cr.html).
Публичная документация описывает текущий модуль; наличие нужных полей API на стенде проверяет подготовка.

Для тестовых Pod используется имеющийся образ `redos_sudo` с
`imagePullPolicy: IfNotPresent`. Команда запуска задаётся явно; sudo не вызывается.

## Запуск

После задания внешних параметров, если они перечислены выше, из каталога `5`:

```bash
bash 01-prepare.sh
bash 02-check.sh
# После фиксации результатов, в том числе при неудаче проверки:
bash 03-cleanup.sh
```

`01-prepare.sh` создаёт тестовые ресурсы; `02-check.sh` выполняет проверки;
`03-cleanup.sh` удаляет только ресурсы этого испытания. Скрипты запускаются независимо.
Повторный полный прогон выполняйте после очистки.

Общие условия и ограничения версии: [README комплекта](../README.md).

# Пункт 54

Платформа предоставляет не менее трех политик безопасности на базе Gatekeeper различных по уровню ограничений, не исключая политику, ничего не ограничивающую

## Что проверит подготовка

`01-prepare.sh` проверит готовность `admission-policy-engine` и регистрацию
webhook `validation.gatekeeper.sh`, затем покажет текущие настройки модуля.
Webhook — обработчик, который получает запрос создания Pod и может его запретить.

После этого подготовка создаст три namespace с уровнями `privileged`, `baseline`
и `restricted` и меткой режима `deny`. Проверять поддержку меток по документации
перед запуском не требуется: `02-check.sh` проверяет их реальное действие
матрицей из девяти запросов к API-серверу.

Запросы используют `create --dry-run=server`: проверки допуска выполняются,
но Pod не сохраняются и небезопасные контейнеры не запускаются.
Если метки не действуют, модуль работает в другом режиме или мешает другая
политика, матрица не сойдётся и проверка завершится с ошибкой.

Зафиксируйте имя constraint (правила Gatekeeper) из ответа API и сопоставьте его
с ресурсом группы `constraints.gatekeeper.sh`, где `enforcementAction=deny`.

| Вариант Pod | privileged | baseline | restricted |
|---|---|---|---|
| privileged: true | Разрешён | Запрет | Запрет |
| Без securityContext | Разрешён | Разрешён | Запрет |
| non-root, drop ALL, seccomp, без escalation | Разрешён | Разрешён | Разрешён |

Критерий: вся матрица совпадает, причины отказа относятся к Gatekeeper и конкретным
нарушениям privilege/non-root/seccomp/capabilities. Forbidden от RBAC, PSA,
ошибка YAML или недоступность webhook не засчитываются. Privileged означает
отсутствие ограничений **этого набора PSS**, а не отключение всех защит кластера.
Если сразу после подготовки метки ещё не попали в кеш Gatekeeper, дождитесь
синхронизации и повторите только проверку; отказ проверки не объявляйте успехом.

Источник: [admission-policy-engine 1.73](https://deckhouse.io/modules/admission-policy-engine/v1.73/).

## Запуск

После задания внешних параметров, если они перечислены выше, из каталога `54`:

```bash
bash 01-prepare.sh
bash 02-check.sh
# После фиксации результатов, в том числе при неудаче проверки:
bash 03-cleanup.sh
```

`01-prepare.sh` создаёт тестовые ресурсы; `02-check.sh` выполняет проверки;
`03-cleanup.sh` удаляет только ресурсы этого испытания. Скрипты запускаются независимо.
Повторный полный прогон выполняйте после очистки.

Общие условия и ограничения версии: [README комплекта](../README.md).

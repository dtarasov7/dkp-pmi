# Пункт 51

Создание изолированного окружения по заготовленному шаблону

## Что делает подготовка

Запустите `bash 01-prepare.sh`. Перед созданием объектов скрипт сам проверит:

1. Модуль `multitenancy-manager`, который создаёт проекты по шаблонам, находится
   в состоянии `Ready`.
2. Kubernetes принимает описание шаблона `ProjectTemplate` версии `deckhouse.io/v1alpha1`:
   доступны поля схемы параметров, текста шаблона и признака его готовности.
3. В описании проекта `Project` версии `deckhouse.io/v1alpha2` доступны поля
   `projectTemplateName` (имя шаблона), `parameters` (значения его параметров)
   и поле состояния проекта.

Проверка выполняется через `kubectl explain` с явным указанием версии API.
Если модуль не готов или поля недоступны, скрипт покажет причину и завершится
**до создания тестовых объектов**. Самостоятельно разбирать схемы перед запуском
не требуется. Скрипт использует API v1alpha2; при наличии только старого варианта
Project понадобится другой сценарий, о чём сообщит подготовка.

На стенде уже используются Cilium и Hubble. Cilium применяет сетевые правила;
фактическую блокировку соединений показывает [пункт 64](../64/README.md).

## Что показать комиссии

Подготовка создаёт собственный шаблон с параметром, квотой и сетевым правилом:
входящий и исходящий обмен разрешён только внутри namespace. Внешний DNS также
закрыт намеренно. Namespace создаёт контроллер Project.
Покажите ProjectTemplate, Project и созданные контроллером ресурсы; сопоставьте
параметр marker с ConfigMap и ownerReferences/служебными метками ресурсов.

Критерий: Project достиг Deployed, параметр перенесён, квота pods=10,
NetworkPolicy содержит ingress и egress только для Pod своего namespace.
Это демонстрация развёртывания шаблона; проверка трафика и прав арендаторов
выполняется в [пункте 64](../64/README.md).

Источник: [Project и ProjectTemplate](https://deckhouse.io/modules/multitenancy-manager/cr.html).

## Запуск

После задания внешних параметров, если они перечислены выше, из каталога `51`:

```bash
bash 01-prepare.sh
bash 02-check.sh
# После фиксации результатов, в том числе при неудаче проверки:
bash 03-cleanup.sh
```

`01-prepare.sh` создаёт тестовые ресурсы; `02-check.sh` выполняет проверки;
`03-cleanup.sh` удаляет только ресурсы этого испытания. Скрипты запускаются независимо.
Повторный полный прогон выполняйте после очистки.

Общие условия и ограничения версии: [README комплекта](../README.md).

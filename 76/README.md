# Пункт 76

Наличие средства контроля соответствия конфигурации кластера рекомендациям CIS Benchmarks.

## Предпосылки

Включён встроенный для поставки стенда механизм проверки CIS (обычно operator-trivy),
выполнено первоначальное сканирование. Наличие только отчётов об уязвимостях образов
не подтверждает CIS Benchmark. У внешних модулей версия отличается от версии DKP;
зафиксируйте фактическую версию и документацию из поставки CSE 1.73.4.

## Демонстрация без создания объектов

```bash
kubectl get moduleconfig operator-trivy -o yaml
kubectl -n d8-operator-trivy get pods
kubectl api-resources --api-group=aquasecurity.github.io
kubectl get crd -o name | grep -i compliance
```

Если зарегистрирован ClusterComplianceReport aquasecurity.github.io:

```bash
kubectl get clustercompliancereports.aquasecurity.github.io
kubectl get clustercompliancereports.aquasecurity.github.io ИМЯ_CIS_ОТЧЁТА -o yaml
```

Не выбирайте первый отчёт автоматически: по spec/status убедитесь, что это
именно CIS Kubernetes Benchmark, его профиль и версия подходят версии Kubernetes
на стенде. Если используется другая API-группа/хранилище отчётов, откройте отчёт
через соответствующий установленной версии UI; не применяйте команды API новой
версии Trivy к старой. Найденный CRD сам по себе не доказывает работу сканирования.

1. В интерфейсе платформы/отчёте откройте CIS-профиль, время последнего запуска,
   перечень проверенных узлов и сводку PASS/FAIL/WARN/SKIP.
2. Раскройте минимум один успешный и один неуспешный либо неприменимый контроль:
   ID пункта CIS, описание, проверенное значение, требование и рекомендацию.
   Если все применимые проверки успешны, выберите ручной контроль и покажите,
   почему он требует подтверждения; искусственно ослаблять кластер не нужно.
3. Для одного FAIL сверяйте конфигурацию компонента на соответствующем узле
   в режиме чтения. Для ручных/непокрытых пунктов укажите необходимость отдельной оценки.
4. Покажите периодичность сканирования и свежий отчёт, сохраните экспорт с датой,
   версиями DKP/Kubernetes/сканера/профиля, результатами и рекомендациями.

## Критерий

Средство выполняет актуальную CIS-проверку и выдаёт воспроизводимые результаты,
включая несоответствия. Наличие FAIL не означает отсутствие средства контроля;
пункт не требует автоматически исправлять все замечания. Отсутствие CIS-профиля
или отчёта означает, что возможность данным испытанием не подтверждена.
Отдельно установленный kube-bench может быть дополнительной проверкой, но не
доказательством встроенного механизма. Скрипты изменения/очистки не нужны.

Текущая публичная документация не является доказательством состава поставки 1.73.4.
